# Validation report

Generated by `tools/validate.py` on 2026-11-23 02:15 UTC.

This report compares slopsix against VDX7 (the primary, hardware-accurate reference) and Dexed (the secondary emulator baseline).
VDX7 emulates the DX7 hardware directly; slopsix should follow it. Dexed is useful as a second opinion: a deviation from Dexed that is no larger than VDX7's own deviation from Dexed is in the expected range.

## Scenario

- sample rate: 49096 Hz (all renderers)
- velocity: 100
- notes: 36 (C2), 60 (C4), 84 (C6)
- note held for 1.000 s, then 1.000 s of tail
- banks: rom1a, rom2a, rom2b, rom3b

## Method

The takes are onset-aligned and compared on two normalised features:

- **Envelope**: RMS in 10 ms windows, normalised to each take's peak and floored at -60 dB. The distance is the mean absolute difference in dB over the windows where both takes are above -55 dB. This is insensitive to output level, which differs between the engines.
- **Spectrum**: the linear energy fraction in 1/3-octave bands from 40 Hz to 8 kHz over a sustain window. The distance is the L1 distance between the band vectors (0 = identical spectral shape, 2 = disjoint).
- **S-D / V-D**: slopsix's distance from Dexed divided by VDX7's distance from Dexed. Values near 1 mean slopsix deviates from Dexed by about as much as VDX7 does.

The 8 kHz upper bound keeps the comparison in the digital engine's band; the hardware's analog output tail (about 16 kHz) is a separate, known open item and is not part of this metric.

Every patch is rendered at each note in the scenario. The per-patch rows aggregate over the notes (the mean of each per-note distance and ratio); the per-octave table shows the median distance of one octave across the whole set. The keyboard level scaling and the envelope rate scaling are note-dependent, so an octave whose distance stands out points at those stages; the outlier lists name the octave. The note sweep covers the DX7's own keyboard span (the 61 keys C2 to C7, MIDI 36 to 96) two octaves at a step.

## Open questions

The remaining open accuracy items in this set are:

- **E-02/E-03/OQ-09**: the exact note-dependent `x` mapping in the EGS
  rate-scaling law, and a hardware capture of the envelope clock.
- **E-05/OQ-25**: the keyboard-level-scaling index space. The engine's
  operator level register still differs from the firmware's on the
  operators with a scaling depth (mean 1.3 register units).
- **O-07**: the 4000 level offset is calibrated against VDX7's raw
  operator signal, not a hardware capture; the absolute level remains
  model-grade.
- **A-02/OQ-20/OQ-27**: the hardware load/read phase and key-on
  persistence of the sum/delay and feedback registers.
- **O-06/OQ-08**: a hardware capture of the feedback level-to-shift path.
- **OU-01/OQ-06**: the compander's exact SF-code numbering and
  saturation/overflow behaviour.
- **T-02**: the hardware evidence set; the comparisons here use VDX7 and
  Dexed as model references.

## Reproducing

```sh
make validate-render
SLOPSIX_VDX7_RENDER=/path/to/vdx7_render \
SLOPSIX_DEXED_RENDER=/path/to/dexed_render \
python3 tools/validate.py --bank ROM1A.syx \
    --bank ROM2A.syx --bank ROM2B.syx --bank ROM3B.syx \
    --note 36,60,84 --out docs/validation.md
```

The reference renderers are external; they are not part of this repository. The renderer used for each reference must implement the command line documented in `tools/validate.py` and render the same note scenario.

Pass `--abc-dir DIR` to also write the A/B/C comparison takes for the report's worst cases: the slopsix, Dexed and VDX7 renders of one take, 0.25 s of silence between them.
